# Cloud Infrastructure Monitoring & Deployment Lab

A hands-on portfolio project that combines Linux system health checks, a small Python monitoring service, Flask, Docker, Docker Compose, and Git/GitHub. Built as a learning project for cloud engineering, networking, and IT infrastructure internships.


## Project at a glance

- **Purpose:** Monitor Linux system health and expose infrastructure metrics through a command-line script and an HTTP endpoint.
- **Monitoring:** CPU, memory, disk, hostname, IP address, and `HEALTHY` / `WARNING` status.
- **Cloud environment:** AWS EC2 running Ubuntu.
- **Automation:** Cron schedules the Bash health report every five minutes.
- **Testing:** Automated Bash test suite with 5 passing tests, including simulated CPU, memory, and disk warnings.
- **Application:** Python, Flask, and Docker.
- **Version control:** Git and GitHub.
> **Scope note:** This is a hands-on cloud engineering learning project. The Bash monitoring script is deployed on an AWS EC2 Ubuntu instance and scheduled with cron to run every five minutes. An automated test suite validates healthy and warning conditions. The Python Flask and Docker components provide an additional containerization and deployment workflow. This is not yet a production monitoring platform.

## Requirements

- Linux or another system with Docker Engine and the Docker Compose plugin
- Git (to clone the repository)
- Internet access when building the image for the first time, to download the base image and Python dependencies

## Run the containerized service

Clone the repository and enter its directory:

```bash
git clone https://github.com/SHAKIB-mac/cloud-infrastructure-project.git
cd cloud-infrastructure-project
```

Build and start the service:

```bash
docker compose -f docker/docker-compose.yml up -d --build
```

Check that the container is running:

```bash
docker ps
docker compose -f docker/docker-compose.yml logs
```

Request the HTTP endpoint:

```bash
curl http://localhost:8000
```

Open `http://localhost:8000` in a browser on the same machine to view the response.

Stop the service when finished:

```bash
docker compose -f docker/docker-compose.yml down
```

## Run the Bash host health report

On a Linux host, run:

```bash
chmod +x scripts/system_health.sh
./scripts/system_health.sh
```

The script reports the current time, hostname, uptime, CPU usage, memory usage, root filesystem usage, IP address, and a threshold-based status. It requires standard Linux utilities such as `top`, `free`, `df`, and `ip`.

## Run automated tests

Run the test suite from the project root:

```bash
./tests/test_system_health.sh
```
The suite checks Bash syntax, normal server health, and CPU, memory, and disk warning conditions.

Latest result: 5 passed, 0 failed.
